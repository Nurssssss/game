# Qonaev Life

Одиночный life simulator с открытым городским миром в Конаеве и модулем изучения
казахского языка. Первая платформа — Windows 64-bit, Unity LTS + URP, single player.

Требования зафиксированы в `.claude/docs/Техническое_задание.pdf` (версия 1.0).
Идентификаторы вида `FR-001`, `NFR-011`, `AT-002` в коде и коммитах ссылаются на
разделы этого документа.

## Текущий этап

**P1 «Прототип систем»** — каркас модулей, Core-сервисы, экономика, язык,
потребности, время и погода с покрытием модульными тестами. Игровые сцены,
контент и UI ещё не собраны.

## Требования к окружению

| Компонент | Версия |
|---|---|
| Unity | 6000.5.5f1 |
| Целевая платформа | Windows 10/11, 64-bit |
| Git LFS | обязателен для бинарных ассетов (NFR-014) |

## Открытие проекта

```bash
git clone <repository-url>
cd FirstProject
git lfs install
git lfs pull
```

Затем откройте папку проекта в Unity Hub версией **6000.5.5f1**. При первом
запуске Unity восстановит пакеты из `Packages/manifest.json` и пересоберёт
`Library/` — это занимает несколько минут.

## Структура проекта

```
Assets/_Project/
├── Core/          Реестр сервисов, шина событий, время, сохранения
├── Content/       ScriptableObject-определения и база контента
├── Features/      Независимые модули: Player, World, Npc, Dialogue,
│                  Language, Economy, Jobs, Quests, Transport, Property, UI, Audio
├── Bootstrap/     Композиционный корень и настройки сессии
├── Editor/        Инструменты команды, проверка контента
├── Tests/         EditMode и PlayMode тесты
├── Art/ Audio/ Scenes/
```

Каждый модуль — отдельная сборка `.asmdef` без циклических зависимостей
(NFR-013). Зависимости направлены снизу вверх: `Core` → `Content` → фичи → `UI`.
Только `Bootstrap` знает обо всех модулях сразу.

### Архитектурные правила

- Монолитного `GameManager` нет. Сервисы создаются в `GameSessionBuilder` и
  общаются через интерфейсы и типизированные события (п. 4.2 ТЗ).
- Текст, цены, расписания и параметры заданий живут в контентных данных, а не в
  коде. Каждая сущность имеет стабильный строковый `Id`.
- В save-файл не попадают ссылки на сцены, префабы и `GameObject` — только
  стабильные ID и сериализуемые значения (п. 7 ТЗ).
- Баланс игрока меняется исключительно через `IWalletService.TryApply`: у каждой
  транзакции есть сумма, причина и источник (FR-050, FR-075).

## Сборка контента

Определения создаются через `Assets → Create → Qonaev Life`. Все определения
регистрируются в ассете `ContentDatabase`.

Перед сборкой запустите проверку данных: **Qonaev Life → Проверить контент**.
Она сообщает о незаполненных ID, пустых локализациях, дублирующихся ключах,
ссылках на несуществующие точки интереса и недостаточном объёме контента
вертикального среза (п. 6 ТЗ, FR-045).

## Запуск тестов

Из редактора: **Window → General → Test Runner**.

Из командной строки (`-quit` указывать нельзя — редактор выйдет до старта
раннера):

```bash
UNITY="/Applications/Unity/Hub/Editor/6000.5.5f1/Unity.app/Contents/MacOS/Unity"

"$UNITY" -batchmode -nographics -projectPath "$(pwd)" \
  -buildTarget StandaloneOSX \
  -runTests -testPlatform editmode \
  -testResults "$(pwd)/Logs/editmode-results.xml" \
  -logFile "$(pwd)/Logs/unity-test.log"
```

Код возврата `0` — все тесты прошли, `2` — есть падения. Проект нельзя
открывать в редакторе одновременно с batch-прогоном.

Покрыты модульными тестами (NFR-011): транзакции и атомарность экономики,
сохранение/загрузка и повреждённые файлы, прогресс языка, внутриигровое время,
потребности, шина событий и реестр сервисов.

## Создание локального сохранения

Сохранения лежат в `Application.persistentDataPath/Saves/slot_<N>.json`.

- macOS: `~/Library/Application Support/<Company>/<Product>/Saves`
- Windows: `%USERPROFILE%\AppData\LocalLow\<Company>\<Product>\Saves`

Слот пишется атомарно через временный файл, поэтому сбой во время записи не
уничтожает предыдущее валидное сохранение. Повреждённый файл не роняет игру:
слот помечается как повреждённый, игрок получает понятное сообщение (FR-004).

## Версионирование ассетов

Бинарные файлы (модели, текстуры, аудио, шрифты) хранятся в Git LFS — список
расширений в `.gitattributes`. Перед первым коммитом убедитесь, что `git lfs
install` выполнен, иначе бинарники попадут в историю напрямую.
